    Functional Requirements¶

    Purpose¶

    This document defines the functional requirements for the Halal-Queue platform.

    Each requirement describes a capability that the system shall provide. Detailed business rules are documented separately in the Business Rules section.

    Requirement Format¶

    Each requirement is assigned a unique identifier.

    Example:

    • FR-001
    • FR-002
    • FR-003

    Functional requirements use the word shall to indicate mandatory behavior.

    1. User Management¶

    Registration¶

    FR-001¶

    The system shall allow users to register using a mobile phone number.

    FR-002¶

    The system shall verify every registration using a One-Time Password (OTP).

    FR-003¶

    The system shall prevent registration using an already registered phone number.

    FR-004¶

    The system shall require users to create a password after successful OTP verification.

    FR-005¶

    The system shall create a customer account after successful registration.

    Authentication¶

    FR-006¶

    The system shall allow users to log in using their verified phone number and password.

    FR-007¶

    The system shall issue JWT access and refresh tokens after successful authentication.

    FR-008¶

    The system shall invalidate refresh tokens during logout.

    FR-009¶

    The system shall reject invalid authentication attempts.

    Password Management¶

    FR-010¶

    The system shall allow authenticated users to change their password.

    FR-011¶

    The system shall support password reset through OTP verification.

    Profile Management¶

    FR-012¶

    The system shall allow users to update their profile.

    FR-013¶

    The system shall support storing:

    • Full name
    • Email address
    • Profile photo (optional)

    2. Vendor Management¶

    FR-014¶

    The system shall allow administrators to approve vendor accounts.

    FR-015¶

    The system shall allow vendors to manage their business profile.

    FR-016¶

    The system shall allow vendors to manage multiple branches.

    FR-017¶

    The system shall allow vendors to configure operating hours.

    FR-018¶

    The system shall allow vendors to temporarily close a branch.

    FR-019¶

    The system shall display vendor availability to customers.

    3. Product Catalog¶

    FR-020¶

    The system shall maintain a global product catalog.

    FR-021¶

    The system shall maintain product categories.

    FR-022¶

    The system shall allow vendors to publish product listings from the global catalog.

    FR-023¶

    The system shall allow vendors to set prices for their product listings.

    FR-024¶

    The system shall allow vendors to mark products as unavailable.

    FR-025¶

    The system shall automatically restore unavailable products to available status during the next scheduled daily reset.

    FR-026¶

    The system shall display only available products to customers for ordering.

    4. Shopping Cart¶

    FR-027¶

    The system shall allow customers to add products to the cart.

    FR-028¶

    The system shall allow customers to update product quantities.

    FR-029¶

    The system shall allow customers to remove products from the cart.

    FR-030¶

    The system shall calculate the cart total automatically.

    5. Order Management¶

    FR-031¶

    The system shall allow customers to place pickup orders.

    FR-032¶

    The system shall generate a unique order number.

    FR-033¶

    The system shall create one or more order items for every order.

    FR-034¶

    The system shall maintain the order lifecycle.

    FR-035¶

    The system shall allow customers to cancel eligible orders.

    FR-036¶

    The system shall maintain order history.

    6. Order Modification¶

    FR-037¶

    The system shall allow vendors to mark ordered products as unavailable.

    FR-038¶

    The system shall allow vendors to propose a reduced quantity for an ordered item.

    FR-039¶

    The system shall require vendors to provide a note when modifying an order item.

    FR-040¶

    The system shall notify customers when an order modification is proposed.

    FR-041¶

    The system shall allow customers to accept a proposed modification.

    FR-042¶

    The system shall allow customers to cancel the affected order item.

    FR-043¶

    The system shall allow customers to cancel the entire order after receiving a modification request.

    7. Pickup¶

    FR-044¶

    The system shall generate a unique pickup code for every accepted order.

    FR-045¶

    The system shall allow vendors to verify pickup using the pickup code.

    FR-046¶

    The system shall mark the order as completed after successful pickup verification.

    8. Notifications¶

    FR-047¶

    The system shall send OTP notifications.

    FR-048¶

    The system shall send order confirmation notifications.

    FR-049¶

    The system shall notify customers about order status changes.

    FR-050¶

    The system shall notify customers when an order is ready for pickup.

    FR-051¶

    The system shall maintain notification history.

    9. Administration¶

    FR-052¶

    The system shall allow administrators to manage product categories.

    FR-053¶

    The system shall allow administrators to manage the global product catalog.

    FR-054¶

    The system shall approve or reject vendor registrations.

    FR-055¶

    The system shall monitor platform activity through an administrative interface.

    10. Background Processing¶

    FR-056¶

    The Worker application shall process asynchronous jobs.

    FR-057¶

    The Worker application shall deliver push notifications.

    FR-058¶

    The Worker application shall execute the daily product availability reset.

    FR-059¶

    The Worker application shall retry failed background jobs.

    Traceability¶

    Each functional requirement shall be traceable to:

    • Business Rules
    • Use Cases
    • API Endpoints
    • Test Cases

    Out of Scope¶

    This document does not define:

    • User interface design
    • API specifications
    • Database schema
    • Implementation details

    These topics are covered by other documentation.
