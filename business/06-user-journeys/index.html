    User Journeys¶

    Purpose¶

    This document describes how users interact with Halal-Queue from a business perspective.

    Each journey defines:

    • Business objective
    • User actions
    • System behavior
    • Expected outcome
    • Exception scenarios

    These journeys serve as the foundation for future use cases, sequence diagrams, APIs, UI design, and testing.

    Journey Overview¶

    ID Journey Primary Actor
    UJ-001 Browse Products Customer
    UJ-002 Place Pickup Order Customer
    UJ-003 Process Customer Order Vendor
    UJ-004 Modify Customer Order Vendor
    UJ-005 Pickup Verification Customer & Vendor
    UJ-006 Manage Product Availability Vendor
    UJ-007 Manage Business Hours Vendor
    UJ-008 Platform Administration Administrator

    UJ-001 — Browse Products¶

    Business Goal¶

    Allow customers to discover products before visiting the store.

    Primary Actor¶

    Customer

    Preconditions¶

    • Customer has opened the application.
    • Vendors are available.

    Business Journey¶

    Customer selects a vendor and browses available products.

    User Journey¶

    1. Open application.
    2. Browse vendors.
    3. Select a vendor.
    4. Browse categories.
    5. View products.
    6. Search products.
    7. View product details.
    8. Customize product.
    9. Add product to cart.

    System Journey¶

    The system shall:

    • Display only available vendors.
    • Display vendor products.
    • Display product images.
    • Display prices.
    • Display quantity types.
    • Display available variations.
    • Prevent unavailable products from being added to the cart.

    Success Outcome¶

    Customer successfully adds products to the cart.

    Exception Journey¶

    • Vendor temporarily closed.
    • Product unavailable.
    • Product archived.
    • Network unavailable.

    UJ-002 — Place Pickup Order¶

    Business Goal¶

    Allow customers to submit a pickup order.

    Primary Actor¶

    Customer

    Preconditions¶

    • Cart contains products.
    • All products belong to one vendor.

    Business Journey¶

    Customer reviews the cart and submits the order.

    User Journey¶

    1. Open cart.
    2. Review products.
    3. Enter an optional order note.
    4. Submit order.
    5. Receive confirmation.

    System Journey¶

    The system shall:

    • Validate the cart.
    • Create a new order.
    • Generate a human-readable order number.
    • Generate a QR code.
    • Generate a pickup code.
    • Notify the vendor.
    • Display order status.

    Success Outcome¶

    Order status becomes Pending Vendor Review.

    Exception Journey¶

    • Vendor closed during checkout.
    • Product becomes unavailable.
    • Validation fails.
    • Network interruption.

    UJ-003 — Process Customer Order¶

    Business Goal¶

    Allow vendors to process customer orders efficiently.

    Primary Actor¶

    Vendor

    Preconditions¶

    • New order received.

    Business Journey¶

    Vendor reviews the order and decides whether to accept, modify, or reject it.

    User Journey¶

    1. Open new order.
    2. Review items.
    3. Review order note.
    4. Accept order OR
    5. Request modification OR
    6. Reject order.

    System Journey¶

    The system shall:

    • Lock the order during processing.
    • Record the decision.
    • Notify the customer.
    • Record audit history.

    Success Outcome¶

    Order progresses to the next valid state.

    Exception Journey¶

    • Vendor loses connection.
    • Order already processed.
    • System error.

    UJ-004 — Modify Customer Order¶

    Business Goal¶

    Allow vendors to resolve stock shortages without cancelling the entire order.

    Primary Actor¶

    Vendor

    Preconditions¶

    • Order contains unavailable items.

    Business Journey¶

    Vendor marks unavailable items and submits a modification request.

    User Journey¶

    1. Open order.
    2. Select unavailable items.
    3. Mark unavailable quantity.
    4. Submit modification.
    5. Wait for customer response.

    System Journey¶

    The system shall:

    • Create an Order Revision.
    • Notify customer.
    • Prevent preparation until customer responds.

    Customer Decision¶

    Customer may:

    • Accept changes.
    • Reject changes.

    Success Outcome¶

    Accepted modifications become the new order version.

    Exception Journey¶

    • Customer rejects changes.
    • Customer does not respond.
    • Modification expires.

    UJ-005 — Pickup Verification¶

    Business Goal¶

    Ensure only the correct customer receives the order.

    Primary Actors¶

    Customer

    Vendor

    Preconditions¶

    • Order status is Ready for Pickup.

    Business Journey¶

    Customer arrives at the store and presents the pickup credential.

    User Journey¶

    Customer:

    1. Open order.
    2. Show QR code OR
    3. Provide pickup code.

    Vendor:

    1. Scan QR OR
    2. Enter pickup code.
    3. Confirm pickup.

    System Journey¶

    The system shall:

    • Validate QR code.
    • Validate pickup code.
    • Prevent duplicate pickup.
    • Record pickup timestamp.
    • Complete order.
    • Notify customer.

    Success Outcome¶

    Order status becomes Completed.

    Exception Journey¶

    • Invalid QR.
    • Invalid pickup code.
    • Order already collected.
    • QR expired (future enhancement).

    UJ-006 — Manage Product Availability¶

    Business Goal¶

    Allow vendors to manage inventory availability.

    Primary Actor¶

    Vendor

    Preconditions¶

    Vendor logged in.

    Business Journey¶

    Vendor updates product availability.

    User Journey¶

    1. Open products.
    2. Select product.
    3. Mark available OR
    4. Mark unavailable.

    System Journey¶

    The system shall:

    • Update availability.
    • Record audit log.
    • Hide unavailable products.
    • Automatically restore manually unavailable products at the beginning of the next business day.

    Success Outcome¶

    Availability is updated.

    Exception Journey¶

    • Product archived.
    • Product deleted.
    • Update conflict.

    UJ-007 — Manage Business Hours¶

    Business Goal¶

    Allow vendors to define operating schedules.

    Primary Actor¶

    Vendor

    Preconditions¶

    Vendor logged in.

    Business Journey¶

    Vendor configures business hours or temporary closures.

    User Journey¶

    1. Open business settings.
    2. Configure weekly schedule.
    3. Add temporary closure.
    4. Enter optional closure reason.
    5. Save.

    System Journey¶

    The system shall:

    • Validate schedule.
    • Publish availability.
    • Prevent ordering while closed.
    • Display closure message to customers.

    Success Outcome¶

    Business availability reflects the configured schedule.

    Exception Journey¶

    • Invalid schedule.
    • Overlapping closure periods.

    UJ-008 — Platform Administration¶

    Business Goal¶

    Maintain platform integrity and operational quality.

    Primary Actor¶

    Administrator

    Preconditions¶

    Administrator authenticated.

    Business Journey¶

    Administrator manages vendors and platform data.

    User Journey¶

    1. Login.
    2. Review dashboard.
    3. Approve vendors.
    4. Manage categories.
    5. Manage Global Products.
    6. Review audit logs.
    7. Monitor platform activity.

    System Journey¶

    The system shall:

    • Record administrative actions.
    • Maintain audit history.
    • Apply role-based permissions.
    • Notify affected users where appropriate.

    Success Outcome¶

    Platform remains operational and properly managed.

    Exception Journey¶

    • Unauthorized access.
    • Validation errors.
    • Concurrent updates.
