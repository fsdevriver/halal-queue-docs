    Development Guidelines¶

    Purpose¶

    To outline the daily development practices, code review expectations, and general guidelines for writing software for Halal-Queue.

    Before Writing Code¶

    1. Read the Documentation: Familiarize yourself with the business rules, system design, and the specific ADRs relevant to your task.
    2. Check for Existing Patterns: If you need to build a new feature (e.g., adding a new entity), look at how similar entities are built within the codebase. Do not reinvent the wheel.
    3. Clarify Requirements: If a business rule is ambiguous, do not guess. Ask the product owner or the software architect.

    Code Review Expectations¶

    When reviewing code, look for:

    1. Correctness: Does the code fulfill the requirements and edge cases?
    2. Architecture: Does the code respect the Clean Architecture boundaries? (e.g., ensure no database logic exists in the presentation controllers).
    3. Testing: Are there adequate unit and integration tests? Do they test failure scenarios, not just the happy path?
    4. Readability: Is the code easy to understand? Are variables named sensibly?
    5. Security: Are inputs validated? Is authorization enforced properly?

    Definition of Done (DoD)¶

    A task is considered "Done" when: - The code is written and meets the coding standards. - Unit and integration tests are written and passing. - The CI pipeline executes successfully. - Code has been reviewed and approved by at least one peer. - The OpenAPI specification has been updated (if API endpoints were modified). - Any relevant business rules or architecture documents have been updated. - The code is merged into main.
